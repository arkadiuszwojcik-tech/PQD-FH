# Contributing to PQD-FH

Thank you for helping improve the Progressive Quality Documentation & Final Handover Framework.

## Report an issue or propose an improvement

Open a GitHub Issue describing:

1. The relevant PQD-FH module, procedure and revision (if applicable).
2. The exact section, appendix or template field concerned.
3. The problem or improvement proposed, including expected practical benefit.
4. Any publicly shareable supporting evidence or references.

For substantial documentation changes, describe the proposal in an Issue before preparing a pull request.

## Controlled-document approach

- A suggested correction, Issue or pull request is **not** a controlled procedure revision.
- The author reviews proposed changes for scope, technical consistency, cross-module dependencies, traceability and compatibility with controlled templates.
- Accepted changes are reflected in the applicable documents, with revision identification and release notes when formally issued.
- Publication timing is determined by review and documentation quality, not by an automatic schedule.
- Existing published documents remain identifiable through their revision and fixed GitHub commit references.

## Confidentiality and third-party rights

Do **not** upload confidential project documents, internal RFI dossiers, personal data, customer information, proprietary drawings, credentials or material you are not authorized to share.

If citing external requirements, provide publicly accessible references where possible. Avoid presenting internal project requirements as universal rules.
